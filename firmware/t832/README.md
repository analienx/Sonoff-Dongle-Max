# T832-KCTRL-R0

Controlled CC2674P10/ZNP firmware candidate for `home-assistant-stack#73`.

T832 is deliberately a **control build**, not a "newer is automatically
better" firmware. Its purpose is to remove SMLIGHT 20260311 downstream
low-level changes while retaining only the coordinator correctness,
restore-compatibility and large-network resource changes that are required
for a meaningful production A/B test.

## Pinned base

- TI SimpleLink Low Power F2 SDK **8.32.00.07**.
- Official TI `LP_EM_CC2674P10` ZNP project seed from the 8.33 examples
  repository because the 8.32 SDK repository does not contain that project
  seed.
- TI ARM Clang **3.2.2.LTS**, SysConfig **1.21.1.3772**, CCS **12.8.0**.
- Koenkk coordinator firmware is a semantic reference only. No giant patch is
  fuzz-applied.

The 8.33 project seed is not trusted implicitly. CI proves byte-for-byte
identity of critical 8.32/8.33 SDK paths, verifies every SDK path referenced
by the seed exists in 8.32, and records the compatibility evidence.

## Included control delta

- NPI UART completion on `UART2_EVENT_TX_FINISHED`.
- UART ISR buffer headroom.
- `NVOCMP_RECOVER_FROM_COMPACT_FAILURE`.
- Extended NV/key MT APIs required by backup/restore.
- Explicit Trust Center, neighbor, route, source-route, route-request,
  device-list, broadcast and conflicted-address capacities.
- MAC and NWK queue headroom.
- Many-to-one concentrator + route-cache baseline.
- 4 KiB C/ISR stack.
- Explicit non-vendor build identity.

Every behavior-changing define is a separate mutation in `manifest.json`
with classification, upstream value, configured value, rationale and required
proof.

## Deliberately *not* changed

KCTRL preserves TI release behavior for unrelated routing/retry/timing policy,
including:

- link-down trigger and route aging;
- route radius/discovery/expiry;
- frequency-agility transmission threshold;
- MTO request rate limit;
- MAC/NWK retry counts;
- APS ACK timing;
- indirect-message timeout;
- multicast enablement;
- source-route expiry.

Those values existed in the broader Koenkk patch, but changing them here would
confound the issue #73 control experiment. They belong in a later, explicitly
classified experiment only if evidence requires them.

Also excluded:

- SMLIGHT 20260311 low-level UART/DMA/FIFO/task changes;
- watchdog recovery;
- runtime diagnostic instrumentation;
- AF/group forwarding changes;
- hard-coded RF power changes.

## Fail-closed build evidence

A successful CI artifact requires all of the following:

1. 100% manifest-to-patcher mutation coverage.
2. No unclassified changed source file.
3. 8.33 project-seed compatibility evidence against the pinned 8.32 SDK.
4. Compiler/linker agreement on **5 NVOCMP pages**.
5. Effective compiler macro proof generated by TI Clang.
6. Successful compile-time assertions for configured capacities.
7. Linker-map proof of `FLASH_NV = 0x2800`.
8. Linker-map proof of a 4 KiB C/ISR stack.
9. Linker-map proof of the configured SRAM safety margin.
10. SHA-256 manifest for the linked OUT, flash HEX and all evidence.

The upstream 8.33 P10 project seed contains a compiler/linker inconsistency:
compiler options specify five NVOCMP pages while linker options specify two.
T832 explicitly patches the linker side to five and refuses to package an
artifact unless the final map proves the expected 5 × 2 KiB NVS region.

A successful CI build is **not authorization to flash production hardware**.
The MR4U board/CCFG/recovery/fresh-backup gates in the issue #73 plan remain
mandatory.
